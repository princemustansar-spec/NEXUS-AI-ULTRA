# Combined personal assistant update

Use **Settings → Personal Assistant** to set a preferred name, friendly/calm/concise reply style, welcome, spoken welcome, routine inclusion, optional online startup headlines and expressive avatar. Welcome runs once per backend session; page refreshes and native floating startup share the same task. Mute, Emergency Stop and a busy voice session prevent it from taking over audio. Ordinary idle capture remains quiet. The existing speech-recognition and playback settings are preserved.

**Apply Windows startup** creates or removes only NEXUS's current-user Startup-folder shortcut, pointing at the updated source installation. It requires no administrator task. It is disabled until explicitly applied; the desktop/floating mode follows the existing setting. Desktop updates retain this path. `pc lock karo` queues the existing approval flow before calling Windows LockWorkStation; the result reports a lock request, not an independently observed screen state.

Daily routines have local HH:MM time and weekday selection. Due notifications and their daily delivery marker commit together, so restarting does not repeat the same day's item. Overdue routines notify after restarting that day. Today reminders come from the existing persistent reminder scheduler. Long-term memory remains explicitly saved in Knowledge & Memory. No default personal schedule is invented.

Voice/chat commands `routine batao`, `aaj ka plan batao`, `news batao`, `pakistan ki news batao`, `international news batao` and `pc lock karo` run through app tools without requiring a capable cloud model. Models also receive daily_briefing, news_briefing and user-approved routine_save tools. General text chat uses the chosen reply style; avatar expressions are lightweight text-based happy/caring/curious/friendly reactions, not audio sentiment detection.

News uses fixed Dawn home and BBC World RSS feeds. It shows original source, date and link, limits headlines to the last 48 hours, caches for ten minutes and reports unavailable feeds. Dawn home can include stories beyond Pakistan. No old cache is silently described as current. Startup fetching requires enabling its online setting; the manual fetch button requests it directly. The voice briefing reads short original headlines rather than inventing a news summary.

**Ollama on this laptop:** Find installed models → choose the model and local/fallback/disabled mode → Save → Test local reply. NEXUS never downloads models automatically. Native loopback calls use a 4096-token context, bounded response, up to two minutes for a cold start and two-minute keep-alive. A local-only selection never silently sends data to a cloud provider. Fallback to local after primary failure is opt-in. Capabilities are read before attaching tools; chat-only models still have the app's explicit commands and confirmation controls. This is separate from installing Claude or obtaining Claude's model.

WhatsApp identifies message rows using observable message IDs rather than requiring legacy message-in/out CSS classes. Nested/quoted IDs, exact contact/message approvals and one-attempt receipts remain guarded. Class-free fixtures reproduce visible history with zero legacy message classes. A live account check on the user's laptop remains necessary; no real message is sent by development tests.
